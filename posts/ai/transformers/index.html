    Attention

    Attention mechanisms are at the core of Transformer models.

      Attention 的职责：跨 token 通信 当前 token 用自己的 Q，去和所有历史 token 的 K 算相似度，然后按权重把它们的 V 加权求和，“混入"自身。经过这一步，h₃’ 里已经包含了 h₁、h₂ 贡献的上下文信息。 关键点：这一步是 token 之间唯一发生信息流动的地方。

    MHA MQA GQA MLA

    https://medium.com/@r9644360/learn-and-code-mha-mqa-and-gqa-a-guide-to-efficient-attention-mechanisms-in-transformers-ff621fe76680 medium.com

       attention算法目前主要有三种变体

    • Multi-Head Attention (MHA) — Each head has independent key-value pairs.
    • Multi-Query Attention (MQA) — All heads share the same key-value pairs, reducing memory usage.
    • Grouped Query Attention (GQA) — A balance between MHA and MQA, where attention heads are grouped to share key-value pairs.
    条件类型
    num_key_value_heads == num_attention_headsMHA
    1 < num_key_value_heads < num_attention_headsGQA
    num_key_value_heads == 1MQA

    flash-attention

    芯片有算力上限和带宽上限，一个算法所需要的浮点运算总量在不考虑带宽限制所需要的时间为$T_{cal}$, 反之对于所需要的内存交换总量所需要花费的时间为$T_{load}$
    如果$T_{cal} < T_{load}$就说明该算法存在访存瓶颈，针对访存进行优化会有明显的效果
    flash-attention就是针对self-atention算法主要在访存上面的优化

    MLP

      MLP 的职责：逐 token 的特征变换 MLP 拿到的输入 h₃’ 已经是一个"融合了上下文的表示”，它对这个向量做非线性变换——完全不看其他 token，也不再有跨序列的通信。 它做的事更像是：把 Attention 整合好的语义信息，投射到模型"知道的概念空间"里。研究者发现 MLP 的权重像一个键值记忆库——某些神经元对应特定知识（比如"巴黎是法国首都"），Attention 定位到相关语境后，MLP 负责把对应的知识"读出来"。

    class Qwen2MoeMLP(nn.Module):
    def __init__(
        self,
        hidden_size: int,
        intermediate_size: int,
        hidden_act: str,
        quant_config: QuantizationConfig | None = None,
        reduce_results: bool = True,
        expert_gate: torch.nn.Linear | None = None,
        is_sequence_parallel: bool = False,
        prefix: str = "",
    ) -> None:
        super().__init__()
        self.gate_up_proj = MergedColumnParallelLinear(
            hidden_size,
            [intermediate_size] * 2,
            bias=False,
            quant_config=quant_config,
            disable_tp=is_sequence_parallel,
            prefix=f"{prefix}.gate_up_proj",
        )
        self.down_proj = RowParallelLinear(
            intermediate_size,
            hidden_size,
            bias=False,
            quant_config=quant_config,
            reduce_results=reduce_results,
            disable_tp=is_sequence_parallel,
            prefix=f"{prefix}.down_proj",
        )
        if hidden_act != "silu":
            raise ValueError(
                f"Unsupported activation: {hidden_act}. Only silu is supported for now."
            )
        self.act_fn = SiluAndMul()
        self.expert_gate = expert_gate

    def forward(self, x):
        gate_up, _ = self.gate_up_proj(x)
        out = self.act_fn(gate_up)
        out, _ = self.down_proj(out)

        if self.expert_gate is not None:
            out = F.sigmoid(self.expert_gate(x)[0]) * out

        return out

    三步合起来就是让模型在高维空间里做一次有选择性的非线性查找，然后把结果写回到 token 的 hidden state。

    RowParallelLinear

    这里的RowParallelLinear是切输入维度(这里的输入维度指的是举证运算的维度) 我们以矩阵运算C(m*n)=A(m*k)@B(k*n), 这里切的就是k轴， 每张卡都到的结果和C的shape保持一致，不过是partial result，需要一次all reduce sum操作

    先从列维度切权重A，每张卡计算的结果相当于按列切分数据，之后从行维度切分权重B, 之后每张卡计算结果相当于只做了矩阵运算中的wise matmul，没有sum操作，所以最终需要一个all reduce sum操作 $\begin{bmatrix} A_{11} \\A_{21} \end{bmatrix} * \begin{bmatrix} B_{11} B_{12} \end{bmatrix}$

    核心思路: 将 A（m×k）按列切分，得到 k 个列向量 a₁, a₂, …, aₖ，每个是 m×1；同时将 B（k×n）按行切分，得到 k 个行向量 b₁ᵀ, b₂ᵀ, …, bₖᵀ，每个是 1×n。 然后将对应的列向量与行向量做外积（⊗），每对产生一个 m×n 的秩-1矩阵，最后把 k 个秩-1矩阵加起来，就是结果 C

    这里的每个外积，也就是$a_{i}b_{i}^{T}$，是一个秩-1矩阵， 这个矩阵的两行之间成比例（第一行 = 第二行 × 2），所以它的"独立方向"只有一个——秩为1。它不是随机的一堆数，而是由一根列方向和一根行方向完全决定的"织物"。

    核心直觉：秩-1矩阵是"一根方向×另一根方向"编织出来的。 想象一块布：纵线是列向量 a，横线是行向量 bᵀ，每个交叉点的数值就是两根线的乘积。这块布的"信息量"极度压缩——

    所有列都是 a 的倍数，列空间只是一条直线； 所有行都是 bᵀ 的倍数，行空间也只是一条直线； 所以整张矩阵只需 m+n 个数（两个向量）就能完整描述，而不是 m×n 个独立数。
