    vLLM主流程

    主流程解析

      vLLM 的主流程可以分为请求调度、模型执行和结果返回三部分。 请求进入后，Scheduler 会根据 max_num_seqs、max_num_batched_tokens 和 KV Cache 空间，把请求组成 batch，并区分 Prefill 和 Decode 阶段。

    在模型执行阶段，每一层 Transformer 先对 hidden states 做归一化，然后通过 QKV Linear 生成 Q、K、V；Q 和 K 经过 RoPE 位置编码，K、V 写入 Paged KV Cache。随后执行 Attention：Prefill 会计算整段输入，Decode 阶段只计算当前 token 的 Q，并读取历史 KV Cache。Attention 输出经过输出投影和残差连接。

    接着进入 MLP，一般是 Gate/Up Projection、激活函数，例如 SiLU，再做 Down Projection，最后加残差。所有 Transformer 层执行完成后，通过 LM Head 得到 logits，再进行采样，生成下一个 token。

    生成的 token 会重新进入 Scheduler。未结束的请求继续参加下一轮 Decode，直到遇到 EOS、达到最大长度或被停止。vLLM 的核心优化主要是 Continuous Batching、PagedAttention、KV Cache 管理，以及 CUDA Graph 等。

    更简化地概括就是：

    请求调度 → QKV 生成 → RoPE → KV Cache 写入/读取 → Attention → MLP → LM Head → Sampling → 下一轮 Decode
