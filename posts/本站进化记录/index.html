    多图排版

    http://snapic.cn/

    Hugo 多图排版这样来 之前采用的是 waterfall.js 和 imgStatus.js 方案，明显的一个弊端是得所有图片完全加载之后才会显示为瀑布流布局。 现已改用 column-count 和 p:has(> img:nth-child） 的纯 CSS 方案，代码少得不得了！ 缺点呢，图片是从上往下、从左往右顺序排列，会导致各列高度明显不一致。试用之后，可以接受！ immmmm.com

    fix:多图分栏通过图片个数来，而非其他元素 https://github.com/1024daniel/1024daniel.github.io.src/commit/6b464ce92898e70084a67fa72a41a35e06888f64 github.com

    email:3435953101@qq.com  
rednote:  
![alt text](/imgs/rednote_qrcode.jpg)

    会渲染成如下样式，m会被错误分割

    原因在于md内容会被渲染成一下html格式

    <p>
  email:3435953101@qq.com
  <br>  <!-- 第 1 个元素 -->
  rednote:
  <br> <!-- 第 1 个元素 -->
  <img src="/imgs/rednote_qrcode.jpg">  <!-- 第 1 个元素 -->
</p>

    原来的css逻辑是, 找到一个段落，其直接子元素中存在一张图片，并且这张图片恰好是第三个元素子节点，整个段落被错误设置为三栏,
    CSS 多栏布局会按可用高度和内容尺寸重新切分文本。由于二维码图片很高、前面的文字很短，浏览器在平衡三栏时把 email 的最后一个字符 m 切到了异常位置

    .post-content p:has(> img:nth-child(3)) {
  column-count: 3;
}

    通过修正逻辑，使用nth-of-type而非nth-child

    .post-content p:has(> img:nth-of-type(3)) {
  column-count: 3;
}

    所以修改以后，只有段落中确实存在第三张图片时才会触发三栏

    <p>
  <img> <!-- 第 1 张图片 -->
  <br>
  <img> <!-- 第 2 张图片 -->
  <span>说明文字</span>
  <img> <!-- 第 3 张图片 -->
</p>

    archives界面介绍

    首先记住几个关键信息

    • Section = content 下的顶层目录名
    • Type = 内容类型（默认等于Section，可覆盖）
    • Kind = 页面种类(page/section/home/taxonomy…)

    ==注意content/posts/a/b.md的Section是posts, content/c.md的Section是""==

    archives详细内容见模版中的themes/hello-friend/layouts/archives/list.html 文章统计代码

    Type默认值就是和Section值一致的，但是md文件内可以指定 type=“notes"来更换值 这里是从所有页面中筛选posts类型且Kind为page的文章，对于_index.md类型文章Kind属于Section不会选中
    文件名是 _index.md 时，Hugo 会把它作为当前目录的列表页/section 页处理，而不是普通文章页

    content/posts/_index.md对应的.Kind == "section" .Section == "posts", 是 section 页面，是branch, 用于描述 /posts/ 这个列表页
    content/posts/a.md通常.Kind == "page" .Section == "posts", 是 regular page, 是 leaf bundle page，也是普通内容页

       主页menu搜索键直接🔍关键词，支持多关键词搜索，多关键词搜素直接空格间隔
    关键词会在文章的title, tags, categories, summary, content和type进行检索命中，不同命中会增加不同权重的scores(相同高于包含, 标题高于内容等等)，且只有关键词都命中了才会有得分， 得分计算函数参考如下

      function scoreItem(item, terms) {
    const title = normalize(item.title);
    const summary = normalize(item.summary);
    const content = normalize(item.content);
    const tags = (item.tags || []).map(normalize);
    const categories = (item.categories || []).map(normalize);
    const type = normalize(item.type);
    let score = 0;
    let matchedTerms = 0;
    terms.forEach(term => {
      let termScore = 0;
      if (title === term) termScore += 80;
      if (title.includes(term)) termScore += 50;

      if (tags.includes(term)) termScore += 70;
      if (tags.some(tag => tag.includes(term))) termScore += 35;

      if (categories.includes(term)) termScore += 45;
      if (categories.some(category => category.includes(term))) termScore += 24;

      if (summary.includes(term)) termScore += 18;
      if (content.includes(term)) termScore += 8;
      if (type.includes(term)) termScore += 4;

      if (termScore > 0) matchedTerms += 1;
      score += termScore;
    });

    return matchedTerms === terms.length ? score : 0;
  }

    album 展示实际拍摄时间

    oss list接口返回的xml文件中只包含图片的最近修改时间，网页显示的时间不是实际拍摄时间

    新增music界面 模拟谜底黑胶效果

    云端存储音频 音频需要保证文件内编码cover，lyrics，title等等信息 代码自动从单文件获取这些metadata来进行渲染呈现界面 对于来源音频不自带这些内容 可以先在网络上获取比如cover，lyrics等信息通过以下命令进行整合成富媒体音频文件

    pack_music() {
  local input="$1"
  local base="${input%.*}"
  local filename="${base:t}"
  local directory="${input:h}"
  local extension="${input##*.}"
  extension="${extension:l}"

  local title="${filename%%-*}"
  local artist="${filename#*-}"

  local cover=""
  local lyrics=""

  for file in "$base.jpg" "$base.jpeg" "$base.png"; do
    [[ -f "$file" ]] && cover="$file" && break
  done

  for file in "$base.lrc" "$base.txt"; do
    [[ -f "$file" ]] && lyrics="$file" && break
  done

  if [[ "$artist" == "$title" ]]; then
    echo "错误：文件名必须使用“歌名 - 歌手”格式"
    return 1
  fi

  local output
  local audio_codec=()

  if [[ "$extension" == "mp3" ]]; then
    output="$directory/$filename.tagged.mp3"
    audio_codec=(-c:a copy -id3v2_version 3)
  else
    output="$directory/$filename.tagged.flac"
    audio_codec=(-c:a flac -compression_level 8)
  fi

  local inputs=(-i "$input")
  local maps=(-map 0:a:0)
  local cover_options=()

  if [[ -n "$cover" ]]; then
    inputs+=(-i "$cover")
    maps+=(-map 1:v:0)
    cover_options=(
      -c:v copy
      -disposition:v:0 attached_pic
      -metadata:s:v:0 title="Album cover"
      -metadata:s:v:0 comment="Cover (front)"
    )
  fi

  local lyric_options=()

  if [[ -n "$lyrics" ]]; then
    lyric_options=(-metadata lyrics="$(cat "$lyrics")")
  fi

  ffmpeg \
    -hide_banner \
    "${inputs[@]}" \
    "${maps[@]}" \
    "${audio_codec[@]}" \
    "${cover_options[@]}" \
    -metadata title="$title" \
    -metadata artist="$artist" \
    "${lyric_options[@]}" \
    "$output"

  [[ $? -eq 0 ]] && echo "生成完成：$output"
}
# 文件名必须是 歌曲名 - 歌手名.扩展名，
# 封面与音频同名，扩展名可以是 .jpg、.jpeg 或 .png
# 歌词与音频同名，扩展名可以是 .lrc 或 .txt
# MP3 输入输出 .tagged.mp3，音频不重新编码
# FLAC、WAV、MP4 输入输出 .tagged.flac，使用无损 FLAC
pack_music "歌曲名 - 歌手名.wav"

    oss-ablum 支持keyword

    https://github.com/1024daniel/1024daniel.github.io.src/commit/908c86e88271a1b2531a9a93638c4972eebe2f1f github.com 数据局建库以及oss album items严格capture time排序manifest json自动存入oss中之后
    oss-album不需要调用oss listobject接口来获取针对prefix符合的items
    而是可以直接可以调用指定相册的manifest json来通过关键字匹配， 不限定prefix 针对杭州album， 推荐样式是

    {{< oss-album title="杭州" prefix="album/" keyword="杭州" limit="16" more="/album/杭州" >}}

    {{< oss-album title="杭州" prefix="album/" keyword="杭州" limit="16" more="/album/杭州" >}}
