    TOC

    修改见:https://github.com/1024daniel/1024daniel.github.io/commit/6379add4beb4706770cedb3311a887d21d08a113

    原来默认文章不会显示大纲导航，需要显示在front matter中添加 toc = true, 且显示在文章开头中间，长文章下滑toc会消失 这里修改默认就显示toc，如果在front matter中添加toc = false会隐藏toc，对于短文章可以考虑设置，且设置toc sticky to right sidebar。 注意这里主题的 .container 设置了 overflow: hidden，会让 position: sticky 失效，所以需要修改为

    .container {
  overflow-x: clip;
  overflow-y: visible;
}

    同时给 .post-body.has-toc 加了：

    overflow: visible;

    archives界面介绍

    首先记住几个关键信息

    • Section = content 下的顶层目录名
    • Type = 内容类型（默认等于Section，可覆盖）
    • Kind = 页面种类(page/section/home/taxonomy…)

    ==注意content/posts/a/b.md的Section是posts, content/c.md的Section是""==

    archives详细内容见模版中的themes/hello-friend/layouts/archives/list.html 文章统计代码

     共计 {{ len (where .Site.RegularPages "Section" "posts") }} 篇日志

    从所有普通页面(RegularPages) 筛选 Section == posts， 也就是从content/posts下所有文章个数(包含子文件夹下面)

        <div id="all-tags">
      {{- range $name, $taxonomy := .Site.Taxonomies.tags -}}
      <a href="/tags/{{ $name | urlize }}">#{{ $name }}<small>({{ .Count }})</small></a>
      {{- end -}}
    </div>

    列出所有的tags

    {{- range  (where (where .Site.Pages "Type" "in" "posts") "Kind" "page").GroupByDate "2006" }}
<div class="post archive__group-posts ">
  <!--content-->>
</div><!--posts-group end-->
{{ end }}

    Type默认值就是和Section值一致的，但是md文件内可以指定 type=“notes"来更换值 这里是从所有页面中筛选posts类型且Kind为page的文章，对于_index.md类型文章Kind属于Section不会选中
    文件名是 _index.md 时，Hugo 会把它作为当前目录的列表页/section 页处理，而不是普通文章页

    content/posts/_index.md对应的.Kind == "section" .Section == "posts", 是 section 页面，是branch, 用于描述 /posts/ 这个列表页
    content/posts/a.md通常.Kind == "page" .Section == "posts", 是 regular page, 是 leaf bundle page，也是普通内容页

    详情可以参考一下命令输出的类型结果示例

    album多图加载解决滑动卡顿 dom重建问题

    • 点击图片仍打开原图：缩略图放在 img src，原图放在外层 a href

    • 滚动时不重建图片 DOM

       主页menu搜索键直接🔍关键词，支持多关键词搜索，多关键词搜素直接空格间隔
    关键词会在文章的title, tags, categories, summary, content和type进行检索命中，不同命中会增加不同权重的scores(相同高于包含, 标题高于内容等等)，且只有关键词都命中了才会有得分， 得分计算函数参考如下

      function scoreItem(item, terms) {
    const title = normalize(item.title);
    const summary = normalize(item.summary);
    const content = normalize(item.content);
    const tags = (item.tags || []).map(normalize);
    const categories = (item.categories || []).map(normalize);
    const type = normalize(item.type);
    let score = 0;
    let matchedTerms = 0;
    terms.forEach(term => {
      let termScore = 0;
      if (title === term) termScore += 80;
      if (title.includes(term)) termScore += 50;

      if (tags.includes(term)) termScore += 70;
      if (tags.some(tag => tag.includes(term))) termScore += 35;

      if (categories.includes(term)) termScore += 45;
      if (categories.some(category => category.includes(term))) termScore += 24;

      if (summary.includes(term)) termScore += 18;
      if (content.includes(term)) termScore += 8;
      if (type.includes(term)) termScore += 4;

      if (termScore > 0) matchedTerms += 1;
      score += termScore;
    });

    return matchedTerms === terms.length ? score : 0;
  }

    album 展示实际拍摄时间

    oss list接口返回的xml文件中只包含图片的最近修改时间，网页显示的时间不是实际拍摄时间
    如果需要展示实际拍摄时间得需要单独的接口来针对指定图片的url进行获取，这是额外heavy操作， 不过可以现在前台渲染最新修改时间 后台逐步刷新替换成实际的拍摄时间 同时在网页鼠标悬停在左上角的时间会展示实际的拍摄时间

    album节点图片显示严格按照capture time排序

    https://github.com/1024daniel/1024daniel.github.io/commit/cf0a19666ed99085916d3a491c2f960b1cb491de github.com

    按capture time时间排序才能对准timeline进行追溯光影，这里使用渐进式加载排序

    • 首屏立即展示，优先使用已有 EXIF 缓存排序。
    • 缺少缓存的 JPEG 在后台以 3 路并发读取拍摄时间。
    • 全部读取完成后统一重排一次，避免频繁跳动。
    • 没有 EXIF 或读取失败时，回退使用 OSS 修改时间。
    • 重排只移动现有 DOM，不会重新下载图片。
    • 已更新静态资源版本，避免浏览器继续使用旧脚本。
